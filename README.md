### 2. Скачивание файла (Download)

#### cURL
```bash
# 1. Получаем подписанную ссылку
DOWNLOAD_URL=$(curl -s "https://functions.yandexcloud.net/d4e54fnlggbipdrp6c19?download=docs/file.pdf" | jq -r .download_url)

# 2. Скачиваем файл
```

#### Python
```python
import requests

url = "https://functions.yandexcloud.net/d4e54fnlggbipdrp6c19"
# Получаем ссылку
response = requests.get(url, params={"download": "docs/file.pdf"})
```

### 3. Загрузка файла (Upload)

*Примечание: Загрузка в папку разрешена только если папка уже существует. Реализована гарантированная однократная загрузка: если файл с таким именем уже существует, S3 вернет ошибку 412 Precondition Failed.*

**Важно:** При загрузке необходимо обязательно передавать заголовок `If-None-Match: *`.

#### cURL
```bash
# 1. Получаем ссылку для загрузки (передаем имя файла и папку в теле JSON)
UPLOAD_INFO=$(curl -s -X POST "https://functions.yandexcloud.net/d4e54fnlggbipdrp6c19" \
     -H "Content-Type: application/json" \
     -d '{"file_name": "test.txt", "folder": "uploads/"}')

UPLOAD_URL=$(echo $UPLOAD_INFO | jq -r .upload_url)

# 2. Загружаем файл с проверкой на существование
curl -X PUT -T "local_file.txt" -H "If-None-Match: *" "$UPLOAD_URL"
```

#### Python
```python
import requests

url = "https://functions.yandexcloud.net/d4e54fnlggbipdrp6c19"
# 1. Получаем ссылку
payload = {"file_name": "test.txt", "folder": "uploads/"}
response = requests.post(url, json=payload)
upload_url = response.json()["upload_url"]

# 2. Загружаем с заголовком If-None-Match
with open("local_file.txt", "rb") as f:
    headers = {"If-None-Match": "*"}
    requests.put(upload_url, data=f, headers=headers)
```

## Управление тегами и конфигурация (Tags Management)

При выводе списка файлов (`list=true`), функция автоматически возвращает теги для каждого объекта.

### Конфигурация разрешенных тегов

В веб-интерфейсе реализована возможность удаления тегов. Список тегов, которые разрешено удалять через UI, настраивается в файле `config/UI-conf.json` в самом бакете.

#### Пример `config/UI-conf.json`:
```json
{
  "allowed_delete_tags": ["error", "processed"],
  "hidden_folder_regex": "^[_.]"
}
```
Если файл отсутствует, по умолчанию разрешено удаление тегов `error` и `finished`.

`hidden_folder_regex` скрывает папки по регулярному выражению для имени папки
на текущем уровне. По умолчанию `^[_.]` скрывает имена с `_` или `.` в начале,
например `_api-tests/` и `.cache/`. `^_` скрывает только имена с подчёркиванием;
`^[.]` — только с точкой. Пустая строка отключает скрытие. Некорректное выражение
оставляет значение по умолчанию и вызывает предупреждение в консоли браузера.
Скрытие действует независимо от пользовательских фильтров и кнопки Clear All,
до пагинации; скрытые папки не входят в отображаемое общее количество.
Файлы не скрываются. Это настройка отображения, а не ограничение доступа к S3.

## Веб-интерфейс (Browsing)

В репозитории есть файл `index.html`, который можно использовать как образец для создания веб-интерфейса.

Особенности:
- **Навигация**: Использует URL hash (`#folder=path/`) для навигации, что предотвращает ошибки доступа (AccessDenied) при обновлении страницы в статическом хостинге S3.
- **Загрузка**: Позволяет загружать файлы с защитой от перезаписи.
- **Теги**: Отображает теги объектов и позволяет удалять разрешенные теги (настраивается через `config/UI-conf.json`).
- **Скачивание**: Позволяет скачивать файлы в один клик.
- **Электронная подпись**: В правом верхнем углу встроен промышленный индикатор SignJS. Он загружает относительную страницу `cloud-sign.html?mode=embedded`, поэтому файлы SignJS должны быть развернуты в том же bucket и каталоге, что и `index.html`.

### Обновление списка файлов

С версии 1.2.0 в левом верхнем углу снова отображается зелёная кнопка «Инь–ян».
Справа остаётся независимый индикатор SignJS. Кнопка обновляет текущую папку,
сохраняя фильтры и сортировку. Во время запроса символ вращается, кнопка сразу
блокируется; после успешной загрузки показывает обратный отсчёт 120 секунд.
Системная настройка уменьшения движения отключает вращение.

Задержка считается отдельно для каждой папки от завершения успешной загрузки.
Время хранится в localStorage с привязкой к странице/API; таймеры прежней версии
`refreshTimer_<folder>` также учитываются. Список хранится в памяти и sessionStorage:
повторный переход в папку и перезагрузка страницы в течение этих 120 секунд
используют сохранённый список, если он доступен. При недоступном хранилище работает
защита в памяти. Если сохранённого списка нет (например, в новой вкладке), первичная
загрузка разрешена. Это клиентская защита интерфейса, а не серверный лимит запросов
и не межвкладочная блокировка.

В версии 1.3.0 список загружается в два этапа. Сначала интерфейс получает все
страницы метаданных (по 500 элементов, без тегов), применяет фильтры по имени и
дате и сортирует результат. Затем последовательно запрашивает теги подходящих
файлов, проверяет фильтры по тегам и сразу показывает каждую подходящую строку.
Порядок строк соответствует выбранной сортировке. По умолчанию на странице
не более 20 элементов (файлов и папок; ссылка на родительскую папку отдельно).
Номера страниц позволяют перейти напрямую; текущая страница выделена,
пропуски обозначены многоточием. Есть кнопки «Предыдущая» и «Следующая».
Теги промежуточных и следующих страниц заранее не запрашиваются.
При фильтре по тегам номера страниц открываются по мере проверки: поиск продолжается до заполнения страницы
или конца списка; общее число совпадений заранее неизвестно. «Следующая» означает,
что остались непроверенные элементы, и может привести к пустой последней странице.
Счётчик показывает только общее число объектов и текущую страницу; ошибка отдельного файла не останавливает
очередь и позволяет повторить запрос только для этого файла. Строка с ошибкой
не считается прошедшей фильтр по тегам и явно помечается как непроверенная.

Изменение фильтров использует уже полученные метаданные и теги. Для ранее
исключённых файлов теги загружаются по необходимости. При смене папки или
фильтров текущая очередь отменяется, запоздалые ответы не меняют новый экран.
Одновременные запросы списка одной папки объединяются.
Ответ предыдущей папки после перехода не заменяет текущий экран. Сетевой запрос
каждой страницы списка и каждого набора тегов ограничен 30 секундами. Ошибка
получения списка не запускает новый двухминутный таймер. Таймер начинается после
получения метаданных, подгрузка тегов продолжается независимо от него. Загрузка
нового файла обновляет список вне ручного ограничения. Изменение или удаление
тега, включая отметку downloadStatus при скачивании, получает итоговый TagSet
в ответе API и обновляет только его строку с повторной проверкой фильтров.

Имена файлов JSON, TXT, BMP, PNG, JPG и JPEG открывают содержимое в новой вкладке.
Браузер получает подписанную ссылку через авторизованный POST и открывает её.
JSON и TXT отдаются как обычный текст, изображения — с соответствующим MIME-типом.
Просмотр не меняет теги объекта. Кнопка скачивания остаётся отдельным действием.

Интерфейс использует единый API v2 на основе SignJS: POST с телом
`{action, params}` и заголовком `X-Api-Key`. URL и ключ вводятся в «Общие настройки
API и SignJS» и сохраняются в `localStorage` под теми же именами, что у SignJS.
В исходниках ключа нет. Поддержка API проверяется командой `capabilities`.
Метаданные: `list-objects-v2`; теги: `get-object-tagging`; изменение одного тега:
`set-object-tag` / `remove-object-tag`; ссылки: `get-preview-url`, `get-download-url`,
`get-upload-url`. AWS-параметры и ответы сохраняют имена `Bucket`, `Key`, `Prefix`,
`Contents`, `TagSet` и `NextContinuationToken`.

Рабочая страница: `https://storage.yandexcloud.net/20ab2a0c-2726-4ba1-9c7c-7deae82941ff/index.html`.

## Скрипты синхронизации (PowerShell)

В репозитории доступны PowerShell скрипты для автоматической синхронизации локальных файлов с S3. Оба скрипта работают в бесконечном цикле (по умолчанию 15 секунд) и защищены lock-файлом от одновременного запуска.

### 1. `sync_worker.ps1` (Загрузка в S3)

Предназначен для мониторинга локальной папки и загрузки новых файлов в S3.
- **Логика**: Ищет файлы (например, `*.json`). При нахождении переименовывает файл в `.processing`, загружает в S3 с защитой от перезаписи (`If-None-Match: *`) и при успехе переименовывает в `.uploaded`.
- **Параметры**:
  - `S3Folder`: (Обязательно) Целевая папка в S3.
  - `MonitorPath`: Локальный путь для мониторинга (по умолчанию сетевой путь 1C).
  - `FileMask`: Маска файлов (по умолчанию `*.json`).
  - `LoopDelaySeconds`: Интервал проверки в секундах (по умолчанию 15).

### 2. `sync_worker_download.ps1` (Скачивание из S3)

Предназначен для скачивания файлов из S3 на основе их тегов.
- **Логика**: Ищет файлы в S3 по маске (например, `*.vdf`, `*.csv`). Скачивает только те файлы, у которых нет тега `downloadStatus` со значениями `downloaded` или `downloading`. Перед началом скачивания устанавливает тег `downloading`, после успешного завершения — `downloaded`.
- **Параметры**:
  - `S3Folder`: (Обязательно) Папка в S3 для сканирования.
  - `LocalPath`: Путь для сохранения файлов (по умолчанию `C:\Downloads\S3Sync`).
  - `FileMasks`: Массив масок (по умолчанию `*.vdf`, `*.csv`).
  - `LoopDelaySeconds`: Интервал проверки в секундах (по умолчанию 15).
